Lesson 2 · Forecasts

The forecast up close: what +4, +10, +20 mean

Why this lesson? Forecasts are the beating heart of Carver's system — every position you'll ever hold traces back to one. When you trade live, you'll read these numbers every day to sanity-check what the system wants to do. In Lesson 1 you watched a raw 4.073 become a capped 20.0. This lesson explains that jump — for real, with the exact code and numbers from your repo.

1 · What a forecast is

A forecast is a single number expressing how strongly, and in which direction, a rule wants to bet. Carver's key move: put every forecast on a common scale so a "+10" always means the same thing — average conviction — no matter which rule or instrument produced it.

+

Positive = go long. Negative = go short. Zero = flat.

10

±10 = an average-strength bet (the whole system is calibrated so the typical absolute forecast is about 10).

20

±20 = the maximum allowed conviction. The forecast is capped here, however strong the signal.

2 · EWMAC — the rule behind your number

ewmac8_32 is a trend rule. It asks: is the recent average price above the longer-term average? If yes, we're in an uptrend → positive forecast. Here is the actual code from your repo (systems/provided/rules/ewmac.py): 

def ewmac(price, vol, Lfast, Lslow):
    fast_ewma = price.ewm(span=Lfast).mean()   # 8-day average (reacts fast)
    slow_ewma = price.ewm(span=Lslow).mean()   # 32-day average (reacts slow)
    raw_ewmac = fast_ewma - slow_ewma          # gap between them = trend strength
    return raw_ewmac / vol.ffill()             # divide by vol to normalise

Two ideas do all the work:

  • Fast minus slow. When price is rising, the 8-day average sits above the 32-day average, so the gap is positive. Bigger gap = stronger trend.
  • Divide by volatility. A 50-point gap means a lot for a calm market and nothing for a wild one. Dividing by vol makes the number comparable across instruments and across time. (This is the same risk-first thinking as stage 1 in Lesson 1.)

3 · Why scale? (raw → ×5.3)

The raw EWMAC number has an arbitrary size — for EUROSTX its long-run average absolute value is only about 1.46. Useless as a common language. So each rule gets a fixed forecast scalar that multiplies it up to the "average ≈ 10" scale. For ewmac8_32 that scalar is 5.3 (right there in your config: forecast_scalar: 5.3). So your last value: 

raw 4.073  ×  scalar 5.3  =  scaled 21.6
Honest nuance — "≈ 10", not exactly 10 The scalar 5.3 is a fixed value Carver calibrated across many instruments, so it targets an average of 10 on average — not per instrument. On EUROSTX specifically the scaled average works out around 7.8. That's expected and fine. (An alternative mode estimates the scalar per instrument; we'll meet that later.)

4 · Why cap? (21.6 → 20)

A scaled forecast of 21.6 is stronger than the ±20 maximum, so forecastScaleCap clips it to 20. This is pure risk control: no matter how euphoric a trend gets, no single rule is allowed to bet more than twice average conviction. That's why Lesson 1's "capped forecast" read exactly 20.0 — the raw signal wanted more, and the cap said no.

raw 4.073  →  ×5.3  →  scaled 21.6  →  cap ±20  →  capped 20.0

Why this matters for going live When you trade live, a screen will show you a combined forecast per instrument (all rules blended — that's Lesson 3). Reading it fluently is your first line of defence: a forecast near ±20 means "max conviction, expect a big position"; near 0 means "flat, expect little or no position." If the position doesn't match the forecast, something's wrong downstream — and you'll know where to look.

See it yourself (5 min)

Prove the EWMAC formula to yourself — rebuild it by hand and watch it match pysystemtrade exactly, then watch the scale → cap chain:

# _learning_sandbox/course/lessons/trace_forecast.py
from systems.provided.futures_chapter15.basesystem import futures_system
s = futures_system()
I, R = "EUROSTX", "ewmac8_32"

price = s.rawdata.get_daily_prices(I)
vol   = s.rawdata.daily_returns_volatility(I)

# EWMAC by hand — the whole rule in three lines
my_raw = (price.ewm(span=8).mean() - price.ewm(span=32).mean()) / vol

pst_raw = s.rules.get_raw_forecast(I, R)
scaled  = s.forecastScaleCap.get_scaled_forecast(I, R)
capped  = s.forecastScaleCap.get_capped_forecast(I, R)

print("my raw    :", round(float(my_raw.iloc[-1]), 3))
print("pst raw   :", round(float(pst_raw.iloc[-1]), 3), "  <- should match!")
print("scaled    :", round(float(scaled.iloc[-1]), 3), "  (raw x 5.3)")
print("capped    :", round(float(capped.iloc[-1]), 3), "  (clipped at +/-20)")

Run it: uv run python _learning_sandbox/course/lessons/trace_forecast.py. Your hand-built forecast will match pysystemtrade to the decimal — you now understand this rule completely.
