The Pipeline: how a price becomes a trade

Why this lesson? Your goal is to trade Carver's system live with real money. Before any of that is safe, you need one unshakeable mental model: a backtest is a pipeline that turns a raw price into a position and a P&L, in seven fixed steps. Live trading runs the same seven steps — it just sends the last step's number to a broker instead of a spreadsheet. Master this and everything downstream (config, rules, costs, going live) becomes "which stage am I touching?"

The one big idea

When you ran system = futures_system() and got a Sharpe ratio, you didn't run "a backtest" as one blob. You ran a chain of seven stages. Each stage is a Python object hanging off system. Each takes the previous stage's output, transforms it, and hands it on. Data flows in one direction:

price → forecast → scaled forecast → combined forecast → position → portfolio → P&L

The seven stages

Each row: the system.stage you call, what it does, and the Carver idea behind it.

1
system.rawdata

Cleans prices and computes volatility (how much each instrument moves per day).

Carver: everything is measured in risk units, so we need vol first.

▼
2
system.rules

Runs each trading rule (e.g. EWMAC) to produce a raw forecast — a number saying "how bullish/bearish, and how strongly."

Carver: a forecast is a risk-adjusted expected return. Positive = go long.

▼
3
system.forecastScaleCap

Scales every rule so its average strength is 10, then caps at ±20.

Carver: a "+10" must mean the same thing for every rule, so they can be compared and combined.

▼
4
system.combForecast

Blends all rules into one combined forecast per instrument (weighted average × diversification multiplier).

Carver: diversifying across rules raises return per unit of risk (the FDM > 1).

▼
5
system.positionSize

Turns the forecast into a number of contracts, sized so each instrument risks the same amount toward your vol target (20%/yr in ch.15).

Carver: volatility targeting — bet size scales with conviction and inversely with risk.

▼
6
system.portfolio

Combines all instruments using instrument weights and the diversification multiplier into final notional positions.

Carver: diversify across instruments too — don't put all risk in one market.

▼
7
system.accounts

Simulates holding those positions over history and computes P&L, Sharpe, and costs (gross vs net).

Carver: judge a system on net risk-adjusted return, after realistic costs.

Why this matters for going live In production, stages 1–6 are identical. The system still computes an "optimal position" for each instrument. The only difference: instead of stage 7 imagining the P&L, a live process compares the optimal position to what you actually hold at Interactive Brokers and sends the difference as an order. So when your live positions look wrong, you debug by asking: which of these seven stages produced the surprise?

See it with your own eyes (5 min)

Run this in your repo. Each line pulls the output of one stage for SP500, so you can watch the price turn into a position. First run is slow (it computes the chain); that's the caching warming up. 

# _learning_sandbox/course/lessons/trace_pipeline.py
from systems.provided.futures_chapter15.basesystem import futures_system
system = futures_system()

# This config trades only 6 instruments; pick one that's actually in it.
I = "EUROSTX"   # European equity index (SP500 is NOT in this universe!)

price    = system.rawdata.get_daily_prices(I)
raw      = system.rules.get_raw_forecast(I, "ewmac8_32")
capped   = system.forecastScaleCap.get_capped_forecast(I, "ewmac8_32")
combined = system.combForecast.get_combined_forecast(I)
position = system.portfolio.get_notional_position(I)

for name, series in [("1 price", price), ("2 raw fc", raw),
                     ("3 capped fc", capped), ("4 combined fc", combined),
                     ("6 position", position)]:
    print(name, "->", round(float(series.iloc[-1]), 3))
Trap you just hit — "has data" ≠ "traded" This config's traded universe is only 6 instruments: CORN, EUROSTX, MXP, SOFR, US10, V2X. An instrument like SP500 has a price CSV on disk, so stages 1–5 will happily compute a forecast and even a subsystem position for it — but stage 6 (portfolio) only holds instrument weights for the 6 in the universe, so get_notional_position("SP500") raises KeyError('SP500'). Always check system.get_instrument_list() first. This is exactly the "which stage produced the surprise?" debugging in action — the error landed at stage 6, which told you it was a portfolio/universe problem, not a data problem.

Run it: uv run python _learning_sandbox/course/trace_pipeline.py

Look at the numbers. The price is in the thousands; the forecasts are small numbers around ±20; the position is a handful of contracts. You just watched a price become a trade. Ask me if any single number surprises you — that curiosity is the lesson.
